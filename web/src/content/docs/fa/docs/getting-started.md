این مستندات محدودهٔ نهایی پیش‌انتشار آزمایشی v0.0.18 را شرح می‌دهند. وضعیت انتشار واقعی و فایل‌های دانلود در GitHub Releases ثبت می‌شوند. این صفحه از نحو پایه و فرمان‌های CLI موجود در v0.0.17 استفاده می‌کند. ابتدا [Ku را نصب کنید](/fa/docs/install/) و مطمئن شوید `ku --version` اجرا می‌شود.

## نوشتن اولین برنامه

فایل `hello.ku` را با محتوای یکسان با `examples/hello.ku` در مخزن بسازید:

```ku
fn main() {
    println("Hello Ku")
}
```

`fn main()` نقطهٔ ورود است. `println` یک خط متن می‌نویسد. Ku از `let` یا `let mut` استفاده نمی‌کند.

## بررسی و اجرا

از پوشهٔ فایل اجرا کنید:

```sh
ku check hello.ku
ku run hello.ku
```

`check` بدون اجرای برنامه، خطاهای واژگانی، نحوی و معنایی پایه را بررسی می‌کند. خروجی استاندارد مورد انتظار هنگام اجرا:

```text
Hello Ku
```

اگر Ku در `PATH` نیست، فایل اجرایی را با مسیر کامل نصب فراخوانی کنید. نام فایل اجرایی Windows برابر `ku.exe` است.

## متغیرها و توابع

این قطعهٔ نحوی پایه را می‌توان داخل `main` قرار داد:

```ku
name = "Ku"
count:int = 3
println(name)
println(count)
```

اولین انتساب، متغیر را تعریف می‌کند. نوع صریح با `name:type = value` مشخص می‌شود. `print` بدون رفتن خودکار به خط بعد می‌نویسد؛ `println` خط جدید اضافه می‌کند.

## ساخت فایل اجرایی

صفحهٔ نصب ابزارهای لازم برای ساخت را فهرست می‌کند. برای مسیر پیش‌فرض:

```sh
ku build hello.ku
```

مسیر پیش‌فرض یک اجراکنندهٔ مفسر را بسته‌بندی می‌کند. کامپایل C بومی به یک کامپایلر C جداگانه نیاز دارد:

```sh
ku build --backend c hello.ku
```

خروجی پیش‌فرض زیر `.ku/build/<profile>/` قرار می‌گیرد؛ از مسیر دقیقی که CLI گزارش می‌کند استفاده کنید. دو مسیر اجرا، پوشش ویژگی متفاوتی دارند. موفقیت `ku check` به معنای موفقیت ساخت بومی نیست.

توجه: دستور `ku build --native hello.ku` **بدون `-o` فقط کد C تولید می‌کند** و پیوند نمی‌دهد. برای نخستین برنامهٔ کامپایل‌شده از فرمان `--backend c` بالا استفاده کنید.

## ساخت پروژه

اگر به پوشهٔ بسته نیاز دارید، از الگوی داخلی استفاده کنید:

```sh
ku create HelloWorld --template basic
cd HelloWorld
ku check
ku run
```

نقطهٔ ورود بسته در `ku.mod` تنظیم می‌شود. `ku create --list` الگوهای موجود را فهرست می‌کند. در حال حاضر فرمان‌های `ku test` و `ku fmt` وجود ندارند.

با [راهنمای زبان](/fa/docs/guide/language/)، [عیب‌یابی](/fa/docs/guide/errors/) و [پشتیبانی از مسیرهای اجرا](/fa/docs/support/) ادامه دهید. خروجی‌های این صفحه نمونه‌های مورد انتظارند و جایگزین بررسی نصب در پلتفرم شما نیستند.
