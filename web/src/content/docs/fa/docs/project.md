این مستندات محدودهٔ نهایی پیش‌انتشار آزمایشی v0.0.18 را شرح می‌دهند. وضعیت انتشار واقعی و فایل‌های دانلود در GitHub Releases ثبت می‌شوند. نام پروژه **Ku programming language / Ku 编程语言** و نام CLI برابر `ku` است. Ku یک زبان برنامه‌نویسی کوچک و مفسر در حال توسعه است. انتشار عمومی فعلی آن پیش‌انتشار آزمایشی v0.0.18 است.

## کد منبع و مجوز

کد خود Ku در نسخه‌های ثبت‌شدهٔ منبع که فایل مجوز را دارند، و افزونهٔ فعلی ویرایشگر، با [Apache License 2.0](https://github.com/fengyanweb/ku/blob/main/LICENSE) (`Apache-2.0`) عرضه می‌شوند؛ برای اطلاعات انتساب، [NOTICE](https://github.com/fengyanweb/ku/blob/main/NOTICE) را ببینید. [کد منبع GitHub](https://github.com/fengyanweb/ku) و [صفحهٔ انتشار](https://github.com/fengyanweb/ku/releases/tag/v0.0.18-r1) را نیز ببینید. اجزای اشخاص ثالث مجوزهای خود را حفظ می‌کنند.

بایگانی‌های v0.0.18-r1 و نسخه‌های قدیمی‌تر، اسناد مجوز اصلی همراه خود را حفظ می‌کنند؛ این تغییر مجوز کد منبع آن بایگانی‌ها را دوباره بسته‌بندی نمی‌کند. استفاده از کامپایلر Ku شما را ملزم به انتشار کد منبع برنامه‌های خود نمی‌کند. هنگام توزیع برنامه‌هایی که کد محیط اجرای Ku را در بر دارند، الزامات مجوز و انتساب مربوط، از جمله اعلان‌های اشخاص ثالث، باید رعایت شوند.

## گزارش مشکل

برای گزارش قابل بازتولید از [Issues](https://github.com/fengyanweb/ku/issues) مخزن استفاده کنید. این موارد را بیاورید:

- نسخهٔ Ku، شناسهٔ Git commit برای کد توسعه و سیستم / معماری مقصد.
- فرمان کامل، مسیر اجرا و کد حداقلی `.ku`.
- پیام تشخیصی کامل یا Error ساختاریافته، خروجی مورد انتظار و خروجی واقعی.
- در مشکل ساخت، نسخهٔ زنجیره‌ابزار Rust / C و وجود واردسازی محلی.

توکن، گذرواژه، رشتهٔ اتصال واقعی یا گزارش دارای دادهٔ حساس تجاری ارسال نکنید. گزارش کارایی باید محیط، بار، روش اندازه‌گیری و نتایج خام را داشته باشد. یک نمونهٔ موفق، توان عملیاتی محیط تولید را اثبات نمی‌کند.

## پیش از مشارکت

[قرارداد نحو](https://github.com/fengyanweb/ku/blob/v0.0.18/docs/syntax.md) و [قرارداد معناشناسی](https://github.com/fengyanweb/ku/blob/v0.0.18/docs/semantics.md) رفتار زبان را تعریف می‌کنند. CI، پیاده‌سازی و قراردادها را با هم بررسی کنید. هدف گزارش کار، ویژگی پیاده‌سازی‌شده نیست.

تغییرها را محدود نگه دارید و بازتولید، علت، محدوده و بررسی را توضیح دهید. محتوای وب‌سایت را همراه کد مرتبط مرور کنید. آزمون‌های موجود، تغییرات درخت کاری و شواهد منحصربه‌فرد را حفظ کنید. پذیرش مشارکت و ترتیبات مجوز را نگهدارنده تعیین می‌کند؛ این وب‌سایت قرارداد مشارکت ابداع نمی‌کند.

این وب‌سایت ایستا است. متن، ناوبری و کد آن به سرور تجاری نیاز ندارند. جست‌وجو نمایهٔ Pagefind را در مرورگر بارگذاری می‌کند؛ سایت اجرای راه‌دور کد Ku ارائه نمی‌دهد.

با [شروع کار](/fa/docs/getting-started/)، [مرزهای پشتیبانی](/fa/docs/support/) و [یادداشت‌های انتشار](/fa/releases/) ادامه دهید.
