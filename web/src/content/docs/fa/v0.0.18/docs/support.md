## پلتفرم‌های CLI منتشرشده

پیش‌انتشار آزمایشی v0.0.18 شامل Windows x64 ‏(MSVC)، ‏Linux x64 ‏(GNU) و macOS arm64 ‏(Apple Silicon) است. هر پلتفرم بایگانی خود را دارد. فایل اجرایی واحدی برای هر سه سیستم وجود ندارد. خروجی پلتفرم‌های دیگر بررسی نشده است؛ [نصب](/fa/v0.0.18/docs/install/) را ببینید.

## مسیرهای اجرا

| قابلیت                              | مفسر `ku run`                   | اجراکنندهٔ پیش‌فرض `ku build`            | C بومی همگام                                     | Task بومی (زیرمجموعه)                            | نمونهٔ اولیهٔ متن LLVM |
| ----------------------------------- | ------------------------------- | ---------------------------------------- | ------------------------------------------------ | ------------------------------------------------ | ---------------------- |
| زبان پایه، توابع، جریان کنترل       | پیاده‌سازی شده                  | مسیر مفسر                                | زیرمجموعه پیاده‌سازی شده                         | زیرمجموعهٔ نوع‌دار محدود                         | نمونهٔ اولیهٔ محدود    |
| JSON                                | پشتیبانی می‌شود                 | پشتیبانی می‌شود                          | پشتیبانی می‌شود                                  | پشتیبانی نمی‌شود                                 | پشتیبانی نمی‌شود       |
| کل گراف واردسازی محلی مستقل از منبع | منبع را بارگذاری می‌کند         | پشتیبانی نمی‌شود؛ فقط ورودی تعبیه می‌شود | هنگام تولید گسترش می‌یابد                        | در محدودهٔ زیرمجموعهٔ پشتیبانی‌شده گسترش می‌یابد | تضمین استقرار ندارد    |
| async / await                       | با محدودیت منابع پیاده‌سازی شده | مسیر مفسر                                | زیرمجموعهٔ ویژه یا رد                            | جزئی، نه async کامل                              | پشتیبانی کامل ندارد    |
| کارخواه PostgreSQL / Redis / MySQL  | دسترسی پایگاه داده ندارد        | دسترسی تفسیری پایگاه داده ندارد          | فقط بومی                                         | انتظار عمومی Task نیست                           | پشتیبانی نمی‌شود       |
| کارخواه TCP / TLS                   | مسیر بومی متناظر ندارد          | مسیر بومی متناظر ندارد                   | پیاده‌سازی C تولیدشده؛ TLS بستهٔ متناظر می‌خواهد | ادعای انتظار عمومی کامل شبکه وجود ندارد          | پشتیبانی نمی‌شود       |

ساخت پیش‌فرض به زنجیره‌ابزار Rust و پیونددهندهٔ متناظر نیاز دارد. C بومی به زنجیره‌ابزار C مقصد نیاز دارد. موفقیت `ku check` کارکرد هیچ‌یک از این ساخت‌ها را اثبات نمی‌کند. وجود فرمان LLVM به معنای مسیر انتشار کامل نیست.

## زیرمجموعهٔ بومی Task

این نسخه مسیر محدود بومی C با `async fn main(): null!` دارد: انواع پایهٔ فهرست‌شده، رشته، آرایهٔ تخت، Results تک‌لایه، شروع/انتقال/awaitِ Task، بخشی از کنترل جریان و کارهای محدود پس‌زمینهٔ فایل/پوشه. TCP/TLS محلی از blocking pool ثابت استفاده می‌کند. این آمادگی عمومی شبکه یا M:N کامل نیست؛ دامنهٔ دقیق در مرجع هم‌روندی همین نسخه است.

انتظار عمومی شبکهٔ Task، اجرای کامل M:N، ترکیب‌های دلخواه هیپ پویا، همهٔ ترکیب‌های capture/تابع ناهمگام و آزمون ماندگاری طولانی کامل هنوز تمام نشده‌اند. زیرمجموعهٔ دقیق پذیرفته و ردشده را در [قرارداد هم‌زمانی](https://github.com/fengyanweb/ku/blob/v0.0.18-r1/docs/concurrency.md) ببینید.

## محدودیت‌های پایگاه داده و شبکه

API پایگاه داده از `module.client(config)?` و سپس متدهای گیرنده استفاده می‌کند و مخزن محدودی داخل کارخواه دارد. بررسی سرور واقعی برای هر درایور، سیستم و commit جداست. ABI ساختگی یا پیوند موفق جایگزین پرس‌وجوی واقعی نیست.

Redis از TCP متن ساده استفاده می‌کند. MySQL در Oracle/MariaDB بررسی گواهی یکسانی که در صورت شکست اعتبارسنجی اتصال را رد کند ندارد. بنابراین اتصال مستقیم باید از loopback، شبکهٔ خصوصی کنترل‌شده یا تونل TLS بررسی‌شده استفاده کند. PostgreSQL راه‌دور به `sslmode=verify-full` صریح و گواهی ریشهٔ معتبر نیاز دارد. TLS بومی در `std.net` به معنای استفادهٔ HTTP، ‏Redis یا مفسر از همان مسیر نیست.

## خودمیزبانی و سازگاری

واژه‌کاو و تجزیه‌گر خودمیزبان Ku زیرمجموعه‌های محدود و بررسی‌های تفاضلی دارند. تجزیه‌گر، بررسی‌کننده، IR و مسیر اجرای کاملِ خودمیزبان هنوز تمام نشده‌اند؛ Rust همچنان زنجیره‌ابزار راه‌اندازی اولیه را فراهم می‌کند. نسخهٔ 0.0.x سازگاری کد منبع یا ABI مربوط به C/FFI تولیدشده را تضمین نمی‌کند.

## دامنه و محدودیت‌های v0.0.18

- JSON: `encode`/`decode` با `stringify`/`parse` مشترک‌اند و اصلاح رفت‌وبرگشت `1e20` موجود است.
- Task بومی همان زیرمجموعهٔ محدود فهرست‌شده است؛ اصلاح پذیرش خاموشی و پاک‌سازی به معنی M:N کامل یا تعلیق عمومی شبکه نیست.
- HTTP آمادگی socket، صف، پاسخ و keep-alive محدود و تشخیص محدود اختیاری دارد؛ این پذیرش همهٔ بارها نیست.
- `ku supervise`، workerهای برنامهٔ کامل، پذیرش، بایت صف، خروجی و پاک‌سازی را مدیریت می‌کند؛ نه worker برای هر درخواست یا Task و نه اعمال خودکار روی `ku run`.

**مشکل شناخته‌شدهٔ HTTP:** خطاهای HTTP 504 ممکن است گاه‌به‌گاه رخ دهند. علت هنوز تأیید نشده است.

### حدود حافظهٔ فرایند

| حدود حافظهٔ فرایند | `ku supervise`                                                                                                                                                                                                                       |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Linux              | حافظهٔ حساب‌شدهٔ هسته در cgroup v2؛ ریشهٔ domain واگذارشده و نوشتنی با `memory`، `pids`، `memory.max`، `memory.swap.max`، `memory.oom.group`، `pids.max` و `cgroup.kill` لازم است. نبود کنترل یا مجوز پیش از اجرای برنامه رد می‌شود. |
| Windows            | Job Objectهای تو‌در‌تو حافظهٔ مجازی تعهدشدهٔ worker و گروه را محدود می‌کنند، نه RSS. commit اولیه پیش از آزادکردن نخ معلق برنامه بررسی می‌شود؛ سیاست میزبان می‌تواند تخصیص Job را رد کند.                                            |
| macOS              | این جداسازی بومی پشتیبانی نمی‌شود و پیش از اجرا رد می‌شود. در صورت نیاز میزبان یا VM لینوکس درست‌پیکربندی‌شده استفاده کنید؛ انتقال خودکار به VM وجود ندارد.                                                                          |

حوزهٔ worker تخصیص‌های Ku و کتابخانه‌های ثالث را حساب می‌کند. معیار cgroup لینوکس و commit ویندوز متفاوت‌اند. `memory.max` ممکن است عبور گذرا را اجازه دهد؛ سقف مطلق تمام حافظهٔ فیزیکی در هر لحظه تضمین نمی‌شود.

هماهنگ‌کننده حد سخت حافظهٔ OS ندارد؛ ذخایر و حساب پذیرش، RSS دقیق نیستند. کل heap هر Task دقیق اندازه‌گیری نمی‌شود و pool، cache و کتابخانه‌ها دقیقاً به هر Task منتسب نیستند. پایگاه دادهٔ بیرونی، میزبان/VM، کامپایلر و `ku run` عادی خودکار زیر بودجهٔ worker نیستند.

اگر OS یک worker را پایان دهد، خطا گزارش می‌شود و ذخایر تنها پس از تأیید پاک‌سازی برمی‌گردند. بعضی تخصیص‌ها زودتر خطا می‌دهند، اما اتمام حافظهٔ کتابخانهٔ ثالث لزوماً Result عادی نمی‌شود. **عملیات پایگاه داده خودکار تکرار نمی‌شود**؛ پایان worker اثبات rollback نیست و اثر جانبی می‌تواند نامعلوم باشد.
