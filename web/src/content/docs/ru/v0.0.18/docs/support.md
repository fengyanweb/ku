## Опубликованные платформы CLI

Экспериментальная предварительная версия v0.0.18 охватывает Windows x64 (MSVC), Linux x64 (GNU) и macOS arm64 (Apple Silicon). Для каждой платформы есть свой архив. Единого исполняемого файла для трёх систем нет. Ресурсы для других платформ не проверялись; см. [установку](/ru/v0.0.18/docs/install/).

Обычная сборка требует подходящих Rust и компоновщика. Нативный C требует инструментов C целевой платформы. Успешный `ku check` не доказывает работоспособность ни одной сборки. Наличие команды LLVM не означает полноценный бэкенд выпуска.

## Нативное подмножество Task

Выпуск включает ограниченный нативный C-путь `async fn main(): null!`: перечисленные примитивы, строки, плоские массивы, одноуровневые Results, запуск/перемещение/await Task, отдельные конструкции управления и ограниченные фоновые операции файлов/каталогов. Локальные TCP/TLS используют фиксированный блокирующий пул. Это не универсальная сетевая readiness и не полное M:N-планирование; точные типы и ожидания приведены в справочнике конкурентности этого выпуска.

Универсальное сетевое ожидание Task, полное выполнение M:N, произвольные сочетания динамической кучи, все сочетания захватов/функций async и полные длительные испытания остаются незавершёнными. Точное принимаемое и отклоняемое подмножество приведено в [контракте конкурентности](https://github.com/fengyanweb/ku/blob/v0.0.18-r1/docs/concurrency.md).

## Ограничения БД и сети

API БД используют `module.client(config)?`, затем методы получателя; внутри клиента находится ограниченный пул. Проверка с реальным сервером выполняется отдельно для каждого драйвера, системы и коммита. Имитация ABI или успешная компоновка не заменяют реальный запрос.

Redis использует незашифрованный TCP. В MySQL нет единообразной проверки сертификатов с обязательным отказом при ошибке во всех Oracle/MariaDB. Поэтому прямые подключения должны использовать loopback, контролируемые частные сети или проверенный TLS-туннель. Удалённый PostgreSQL требует явного `sslmode=verify-full` и доверенных корневых сертификатов. Нативный TLS в `std.net` не означает, что HTTP, Redis или интерпретатор используют тот же путь.

## Самохостинг и совместимость

Самостоятельно реализованные на Ku лексер и парсер имеют ограниченные подмножества и дифференциальные проверки. Полные собственные парсер, проверяющий модуль, IR и бэкенд пока не завершены; инструменты начальной загрузки всё ещё предоставляет Rust. Версия 0.0.x не обещает совместимость исходников или сгенерированного C/FFI ABI.

## Объём и ограничения v0.0.18

- JSON: `encode`/`decode` используют `stringify`/`parse`, включая исправление обратного преобразования `1e20`.
- Нативные Task остаются перечисленным ограниченным подмножеством; исправления допуска при завершении и очистки не означают полное M:N или универсальное сетевое ожидание.
- HTTP предоставляет ограниченные socket readiness, очереди, ответы и keep-alive с необязательной ограниченной диагностикой; это не полная приёмка нагрузок.
- `ku supervise` управляет workers целых программ, допуском, байтами очередей, выводом и очисткой; это не worker на запрос или Task и не автоматическое ограничение `ku run`.

**Известная проблема HTTP:** периодически могут возникать ошибки HTTP 504. Причина пока не установлена.

### Ограничения памяти процессов

| Ограничения памяти процессов | `ku supervise`                                                                                                                                                                                                                                             |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Linux                        | Память по учёту ядра cgroup v2; необходим доступный для записи делегированный корень домена с `memory`, `pids`, `memory.max`, `memory.swap.max`, `memory.oom.group`, `pids.max`, `cgroup.kill`. Отсутствие прав или контролей блокирует запуск приложения. |
| Windows                      | Вложенные Job Objects ограничивают workers и группу по выделенной виртуальной памяти commit, а не RSS. Начальный commit проверяется до запуска приостановленного потока; политика хоста может отклонить назначение Job.                                    |
| macOS                        | Режим изоляции нативно не поддерживается и отклоняется до запуска приложения. При необходимости используйте настроенный Linux-хост или VM; автоматической передачи в VM нет.                                                                               |

Домен worker учитывает выделения Ku и сторонних библиотек. Учёт Linux cgroup и Windows commit — разные показатели. `memory.max` может допускать кратковременное превышение; абсолютный предел всей физической памяти в любой момент не гарантирован.

У координатора нет жёсткого лимита памяти ОС; резервы и учёт допуска не являются точным RSS. Весь heap одной Task точно не измеряется; пулы, кэши и выделения библиотек нельзя точно отнести к отдельной Task. Внешние БД, хост/VM, компиляторы и обычный `ku run` автоматически не ограничены бюджетом worker.

Если ОС завершает worker, координатор сообщает ошибку и возвращает резервы лишь после подтверждённой очистки. Некоторые выделения могут отказать заранее, но нехватка памяти в сторонних библиотеках не обязательно превращается в обычный Result. **Операции БД никогда автоматически не повторяются**; выход worker не доказывает откат, побочные эффекты могут оставаться неизвестными.
