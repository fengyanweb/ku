# Ku 0.0.16

0.0.16 的重点是**补齐 native 标准库**、**接入数据库驱动(PostgreSQL / Redis / MySQL,含连接池)**,并通过路径级所有权分析与对抗式审计加固内存/资源安全。目标始终是:开发快速、占用资源小、稳定、安全。

> **验证状态说明(重要)**:本版本的数据库驱动为 native-only 的新功能,各驱动的真实验证程度不同,请以下表为准,不要把「已实现」等同于「已在生产验证」。
>
> | 驱动 | 验证程度 |
> |---|---|
> | **std.pg** | 已对真实 PostgreSQL(含阿里云 RDS + SSL)端到端跑通 connect/query/参数化/连接池,并经 CRT 循环压测 0 泄漏 |
> | **std.redis** | 已对真实 Redis 服务器端到端跑通 auth/set/get/del,含 `\r\n`/二进制值往返,CRT 循环压测 0 泄漏 |
> | **std.mysql** | **仅编译+链接+连接握手+错误路径验证**(连到真实 MySQL 但因无测试凭据,`query`/`value` 的成功路径**从未实际执行**)。视为**实验性**,投产前必须先对一个可访问的 MySQL 实测查询与取值。 |

## 数据库驱动(std.pg / std.redis / std.mysql)

采用「C 库薄封装 + 显式 API」策略,连接、结果集都是**不透明的 owned 句柄**,离开作用域自动关闭/释放。

### PostgreSQL(std.pg,绑定 libpq)

```ku
import pg from "std.pg"
fn main(): null! {
    conn = pg.connect("host=... dbname=... user=... password=... sslmode=require")?
    // 参数化查询(唯一注入安全写法,$1..$N 占位符)
    res = pg.query_params(conn, "SELECT id, name FROM users WHERE id = $1", ["42"])?
    println(pg.rows(res))          // 行数
    println(pg.value(res, 0, 1))   // 第 0 行第 1 列(文本值)
    pg.close(conn)
    return ok(null)
}
```

- `pg.connect(conninfo) : PgConn!`、`pg.query(conn, sql) : PgResult!`、`pg.query_params(conn, sql, [str]) : PgResult!`、`pg.rows/cols(res) : int`、`pg.value(res, row, col) : str`、`pg.close(conn)`。
- `pg.query` 直接拼接 SQL 有注入风险;需要绑定值时**必须**用 `pg.query_params`(经 `PQexecParams` 服务端绑定)。
- **连接池**:`pg.pool(conninfo, size) : PgPool!`、`pg.pool_query(pool, sql)`、`pg.pool_query_params(pool, sql, [str])`、`pg.pool_close(pool)`。池独占所有连接,每次查询内部借-查-还,调用方不持有裸连接,**构造上不可泄漏**;有界阻塞池,连接用尽时等待空闲。
- 链接路径自动探测:`KU_PG_LIB` 环境变量 → `pg_config --libdir` → 常见安装目录。运行时需 `libpq.dll` 在 `PATH`。

### Redis(std.redis,自实现 RESP-over-socket,零外部依赖)

```ku
import redis from "std.redis"
fn main(): null! {
    conn = redis.connect("127.0.0.1", 6379)?
    redis.auth(conn, "password")?
    redis.set(conn, "key", "value")?
    println(redis.get(conn, "key")?)   // value(缺失键返回空串)
    redis.del(conn, "key")?
    redis.close(conn)
    return ok(null)
}
```

- 直接在 Winsock 上实现 RESP 协议(与 native HTTP 同一套 socket 基建),不依赖 hiredis。
- `redis.connect(host, port)`、`redis.auth/set/del`、`redis.get`、`redis.close`。命令参数长度前缀编码,含 `\r\n`/二进制的值可安全往返,不会被当作协议注入。

### MySQL(std.mysql,绑定 libmysqlclient)—— ⚠️ 实验性,happy-path 未验证

- API 形状与 pg 对齐:`mysql.connect(host, port, user, password, db)`、`mysql.query/query_params/rows/cols/value/close`。
- `mysql.query_params` 用 `mysql_real_escape_string` 逐参数转义并加引号(设计上注入安全)。
- **诚实声明**:本驱动目前**只验证到「能编译链接 libmysql、能连上真实 MySQL 服务器、错误(认证失败)路径正确返回并 0 泄漏」**。由于没有可用的测试凭据,`mysql.query` / `mysql.value`(内部用 `mysql_data_seek` + `mysql_fetch_row` 游标取值)的**成功查询路径从未真正执行过**,其正确性与内存行为**尚未验证**。请勿在未对一个可访问 MySQL 实测之前用于任何真实场景。
- 链接路径:`KU_MYSQL_LIB` 环境变量 → 常见 `MySQL Server */lib`。运行时需 `libmysql.dll` 在 `PATH`。

## native 标准库补齐

- **`str()`**:整数、布尔、字符串、null 转字符串,逐字对齐解释器(如 `str(-5)` → `"-5"`、`str(true)` → `"true"`)。
- **字符串方法(6/9)**:`len`(Unicode 码点计数)、`contains`、`starts_with`、`ends_with`、`replace`、`slice`(char 索引、越界返回 Result 错误)。`trim`/`lower`/`upper` 因需 Unicode 大小写/空白表,native 暂以明确错误提示,不静默偏离解释器。
- **struct 复杂字段**:支持 `[int]`/`[str]` 等基本数组字段、`[Person]` 结构体数组字段、`[[int]]` 嵌套数组字段,以及 `enum` 字段(统一拓扑发射解决 struct↔enum 布局依赖)。深拷贝/释放自动递归。
- **模板字符串**:`` `Hello {name}, age {n}` `` 在 native 下正确插值(解糖为 `str()` 拼接),此前只有解释器支持。
- **字符串字面量修复**:含非 ASCII / 非打印字符(NBSP、组合符、零宽字符等)的字面量此前在 native 下被错误转义,现已修正,`len`/`contains` 等结果与解释器一致。

## 稳定与安全

- **所有权 checker**:路径级部分 move 分析(`name = user.name` 后 `user.name` 不可用而 `user.age` 仍可用),控制流合并 initialized/moved/maybeMoved,索引位置要求显式 `.clone()`,闭包捕获值不可移出。checker 作为所有权第一道防线,backend 只执行已验证合法的 move。
- **内存/资源泄漏修复(经 CRT + ASan + 多智能体对抗式审计)**:
  - 修复循环内 `catch (e)` 错误绑定未释放旧值导致的累积泄漏。
  - 修复 `?` 解包(借用形式,如 `pg.rows(pg.query(...)?)`)在循环内覆盖临时量前未释放旧值导致的泄漏——服务器热路径的关键修复。
  - 修复 `array.push` owned 字面量元素未被释放的泄漏。
  - **std.pg** 的连接/结果集/连接池、**std.redis** 的连接/命令,均经 CRT 循环压测 0 泄漏验证;**std.mysql 仅验证了连接失败路径 0 泄漏,成功查询路径的内存行为尚未验证**(见上文验证状态表)。
  - 上述泄漏是对抗式审计发现的真实缺陷,已修复并回归;但「安全」是持续过程,不代表已穷尽所有问题。

## 兼容性说明

- 数据库驱动目前为 native-only(`ku build --native`),解释器 `ku run` 暂不支持连库。
- 数据库返回值均为文本(str);类型化列、连接池扩展到 redis/mysql 等留待后续版本。
