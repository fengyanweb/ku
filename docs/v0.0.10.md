# Ku 0.0.10

0.0.10 继续推进 0.0.x 的 native 前置工作：先把闭包、Result 控制流、package lock 和 C 后端子集做稳，再评估 async / LLVM。

## 已完成

- 运行时闭包从保存整个 `Env` 改成精确 capture map。局部递归函数只在调用时临时注入 self binding，降低 Rc 自环风险。
- `?` 的 IR lowering 从表达式 temp 推进为显式 `ResultBranch`，ok 分支用 `BindOk`，err 分支用 `PropagateErr` 或跳到 try handler。
- native C 原型后端扩展到基础 `if` / `while` / 纯 int 函数子集，并继续明确拒绝 Result、闭包、struct/enum、数组等未稳定 ABI 的节点。
- `ku.lock` 增加本地 import 依赖列表和稳定内容 hash 形式的 import cache key。
- enum `match` 增加基础穷尽性检查：没有 `_` 时必须覆盖所有未带 guard 的 variant。
- 新增 v0.0.10 回归测试，覆盖闭包捕获、Result CFG、match 穷尽性、C 后端 if/while 子集和 package lock 依赖记录。

## 当前边界

- async / await 还没有做：需要任务模型、事件循环和阻塞 stdlib 边界。
- LLVM 后端还没有做：需要 Result ABI、闭包 ABI 和类型布局继续稳定。
- 远程 package 还没有做：需要版本解析、下载校验和缓存淘汰策略。
- 复杂嵌套模式、match guard 模式矩阵和完整穷尽性检查还没有做。
- native C 后端仍是原型：当前只覆盖小的纯值子集，不承诺生成完整生产级 C。

## 下一步

1. 固定 Result ABI，让 `ResultBranch` 能进入 native C / LLVM。
2. 给 `try/catch/finally` 做完整 CFG lowering，特别是 finally 后继续传播错误的路径。
3. 设计闭包 ABI，决定捕获值、引用捕获和异步边界的所有权模型。
4. 扩展 package：远程依赖、版本解析、下载校验、缓存淘汰。
5. 继续完善 `match` 模式矩阵，覆盖嵌套模式、guard 和不可达分支诊断。
