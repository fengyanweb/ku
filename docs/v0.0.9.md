# Ku 0.0.9

0.0.9 继续推进 native 后端前置，但仍然坚持先做 IR 和 ABI，不直接跳完整 C / LLVM。

## 已完成

- IR 增加稳定临时值 `%tN`，非叶子表达式会先降成 typed temp。
- IR 增加 `Print` 指令，后端不再把打印语句和普通表达式混在一起。
- IR 增加 struct / enum layout table，记录字段 offset、enum tag 和字段类型。
- `for`、`try/catch/finally` 在 IR 中有结构化标记，不再简单写成 `unsupported`。
- stdlib metadata 增加 ABI 和失败模式：`Never`、`ReturnsResult`、`MayPanic`。
- IR 的 dotted stdlib 调用会复用 metadata 推导返回类型，例如 `array.try_get` 是 `T!`，`string.slice` 是 `str!`。
- 局部函数 IR 捕获改成自由变量分析，不捕获参数、函数内局部变量、for 变量、catch 变量。
- package 第二阶段增加 `version` 字段和 `ku.lock` 本地锁文件。
- 新增 `ku build --native <file.ku>`，输出 prototype C 源码。

## native C 原型范围

当前 native C 后端只支持很小子集：

- `int` / `bool` / `str`
- 局部变量
- 算术、比较和逻辑表达式
- 直接函数调用
- `print`

遇到数组、struct、enum、Result、`?`、try、match、闭包等复杂节点会明确报 `native C prototype` 不支持。它是后端入口和 ABI 验证点，不是完整 native 编译器。

## 仍未完成

- async / await：还缺任务模型、事件循环和阻塞 stdlib 边界。
- LLVM 后端：需要 IR 更稳定后再做。
- 引用捕获闭包的 Rc 自环彻底治理：当前 IR 捕获已精确，运行时仍需要把 `Value::Function` 从保存整个 `Env` 改成保存 capture map / weak self binding。
- `?` 的失败路径还没有完全降成显式 CFG block，当前 IR 仍保留 `TryUnwrap` temp。
- 复杂嵌套模式、match guard 和穷尽性检查仍需要完整模式矩阵。
- 远程 package、版本解析、下载校验和缓存淘汰还没有做。

## 下一步

1. 把运行时闭包从捕获整个 `Env` 改成精确 capture map，解决 Rc 自环风险。
2. 把 `?` / `try` 降成显式 ok/err CFG，native 后端才能支持 Result。
3. 扩展 C 后端到 if/while 和纯 int 函数子集。
4. 给 `ku.lock` 增加依赖列表和 import cache key。
5. 在 IR 上补 match 穷尽性检查需要的类型信息。
