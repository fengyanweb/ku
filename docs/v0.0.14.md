# Ku 0.0.14

> 历史版本说明：本页保留 0.0.14 当时的接口快照，不代表当前语法。当前普通 HTTP handler 只允许 `fn()` 或 `fn(req)`；请以最新文档和编译器检查结果为准。

0.0.14 的重点是把用户能直接写项目和 HTTP server 的路径闭合：项目模板命令、HTTP handler 写法、HTTP 状态码 helper、解释器版本和 VS Code 插件版本保持同步。

## 项目模板命令

新增：

```powershell
ku create <name>
ku create <name> --template <template>
ku create --list
ku init
ku init --template <template>
ku template list
```

内置模板：`basic`、`cli`、`http`、`json`、`fs`、`lib`。

规则：

- `ku create` 创建新目录。
- `ku init` 初始化当前目录。
- `ku run` 只负责运行当前 package 或指定 `.ku` 文件，不负责创建项目。
- `ku check` / `ku run` 无参数时读取当前目录向上的 `ku.mod` 入口。

`ku.mod` 新增可选字段：

```txt
template = "http"
type = "lib"
```

## HTTP server

`http.service()` 是创建 service 对象的唯一写法。旧的 `http.service` 属性式默认对象已移除；如果写 `app = http.service`，检查阶段会报错并提示改成 `http.service()`。

后续 0.0.x 已删除早期的双参数 `fn(req, res)` 占位 ABI，不提供兼容入口。当前文档和普通业务代码统一使用 `fn()` / `fn(req)` 两种签名；可以传顶层函数名，也可以内联。其他函数值语法即使作为 handler 传入，也必须满足同样的参数、返回值与只读捕获检查：

```ku
fn ret() {
    return http.text("Ku HTTP OK")
}

app.get("/", ret)
app.get("/index", fn() {
    return http.text("Ku HTTP 123")
})
app.get("/json", fn(req) {
    return http.json({ code: 0, msg: "ok", path: req.path, data: null })
})
```

`req` 是请求对象，包含 `method/path/params/query/headers/body`。响应只通过返回 `http.text/json/empty/redirect(...)` 产生；普通 handler 不接收 `res` / `writer` 参数。

## HTTP 状态码

新增：

```ku
http.status.ok
http.status.created
http.status.noContent
http.status.notFound
http.status.internalError
http.statusText(http.status.notFound)
http.empty()
http.redirect("/login")
```

`http.text(body)` / `http.json(body)` 默认 HTTP status 为 200；`http.text(status, body)` / `http.json(status, body)` 用第一个参数显式设置协议状态码。`http.empty()` 默认 204，`http.redirect(location)` 默认 302。

业务响应体里的 `code/msg/data` 由开发者自己维护；Ku 只维护 HTTP 协议状态码和 runtime 能判断的自动错误，例如 404、405、413、431、500、503、504。
