# Ku 0.0.19

[中文](https://github.com/fengyanweb/ku/blob/v0.0.19/docs/v0.0.19.md) · [Known issues](https://github.com/fengyanweb/ku/blob/v0.0.19/docs/v0.0.19-known-issues.en.md)

0.0.19 is an **experimental prerelease** collecting the existing runtime, HTTP, database and service-management work for controlled evaluation. It is not a general production-readiness endorsement. The 0.0.x series does not promise compatibility for source, generated C or the internal Task ABI; rebuild native programs after upgrading.

## Scope

- **Native Task**: the implemented async source subset, bounded driver, deadlines, cancellation and cleanup, plus selected file, timer and network-wait paths. Full M:N scheduling, fully suspendable interpreter execution and general I/O coverage remain incomplete; see the [concurrency contract](https://github.com/fengyanweb/ku/blob/v0.0.19/docs/concurrency.md).
- **Native HTTP**: multiple event loops with fixed connection ownership, HTTP/1.1 connection reuse, admission and buffer budgets, and the existing Task-handler adapter. This includes the implemented owner-wakeup, readiness, retirement and reclamation fixes; it does not guarantee scaling or latency for every workload. See the [runtime notes](https://github.com/fengyanweb/ku/blob/v0.0.19/docs/multiloop-runtime.md).
- **PostgreSQL**: native synchronous and resumable asynchronous pooled operations, bounded waiting, error/cancellation handling and connection metrics. Existing private-database examples cover reads/writes, Chinese text/null, large results, disconnects and recovery of new requests. Those results apply only to their recorded artifacts and environments, not a complete database/platform matrix.
- **Service operation**: `ku service` provides probes, authorized status/metrics access, child-process replacement and orderly stopping; deployment tools provide draining, rolling updates, rollback and bounded monitoring. `ku supervise` runs whole programs as workers with explicit admission, deadlines and platform resource limits. These commands have distinct roles; see [service deployment](https://github.com/fengyanweb/ku/blob/v0.0.19/deploy/service/README.md) and [process execution](https://github.com/fengyanweb/ku/blob/v0.0.19/docs/process-execution.md).
- **JSON**: the previous implementation remains the default. `json.encode()` / `json.decode()` share the existing implementation, including the fix that makes encoded `1e20` decodable again. yyjson is not restored as the default.

Database operations are not automatically retried. A lost connection, cancellation or worker termination can leave database effects unknown; a process exit does not prove transaction rollback.

## Download and install

This release targets the following official packages. The actual [GitHub Release](https://github.com/fengyanweb/ku/releases) attachments are authoritative:

| System / architecture | Target |
| --- | --- |
| macOS / Apple Silicon ARM64 | `aarch64-apple-darwin` |
| Linux / x64 | `x86_64-unknown-linux-gnu` |
| Windows / x64 | `x86_64-pc-windows-msvc` |

Linux ARM64 is a source-build environment used for performance work and isolated rehearsals, **not a fourth official package in this release**.

Download `ku-v0.0.19-<target>.tar.gz`, its manifest and `SHA256SUMS` for your target. Verify the checksum, then extract into a separate directory. Follow the included `README-INSTALL.md` and preserve the layout of the CLI, companion libraries, `deps/` and native TLS files. Install the bundled VSIX for VS Code support. Run `ku version` and check for `0.0.19`. Native C builds still require a target C toolchain; database programs also require the appropriate client libraries. Database servers are not included.

## Verification and release boundaries

Existing installation, real service-chain, PG-recovery and resource-reclamation results are summarized in the [RC verification notes](https://github.com/fengyanweb/ku/blob/v0.0.19/docs/production-rc/verification-summary.md). The historical `rc_prepared` state describes an isolated example, without a real application canary; it is not verification of the final 0.0.19 artifacts or production acceptance.

In the last valid short recheck on 2026-10-28, without perf or injected probes, all 60,000 short requests in the cancellation phase were correct. Their p99 was **1.557 ms**, but the maximum was **98.809 ms**, with 169 requests above 20 ms. Post-overload recovery also retained tail spikes. This does not supersede the historical failed formal window. The five candidate windows and formal 30-minute acceptance remain incomplete.

This round completed one serial fixed-load comparison of Ku, Go, Rust, Node, Java, .NET and C++: 28 measured windows and 583,800 correct requests. Relative results differ across CPU, JSON and database work. The [bilingual performance report](https://github.com/fengyanweb/ku/blob/v0.0.19/docs/performance-v0.0.19.en.md) retains actual host paging and request tails. This bounded comparison is not maximum-capacity or sustained-stability acceptance.

The Release body and asset manifests report the actual final commit, tag, packages and required CI results. This page does not mark them as passed in advance. See [known issues](https://github.com/fengyanweb/ku/blob/v0.0.19/docs/v0.0.19-known-issues.en.md) for historical HTTP 504s, the two paused areas and resource guarantees. Website changes in this round are code and packaging only; they have not been deployed.
