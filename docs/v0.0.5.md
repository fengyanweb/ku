# Ku v0.0.5 记录

## 已完成

- 解释器版本同步到 `ku 0.0.5`。
- 新增可恢复错误语法：`T!`、`?`、`try/catch/finally`、`fail`。
- 新增不可恢复崩溃语法：`panic`。
- 新增 `ok(value)`、`err(message)` 和 `fs.try_read(path)`。
- `?` 支持在返回 `T!` 的函数中传播，也支持在 `try` body 内传播到就近 `catch`。
- `?` 会短路当前表达式，避免失败后继续执行右侧调用。
- `match` 支持 guard：`Pattern if condition => value`。
- 未捕获的可恢复错误会报 `unhandled recoverable error`，不会静默成功。
- 调低函数调用深度上限到 16，避免 Windows debug 栈在递归保护触发前溢出。
- 补充 v0.0.5 测试，覆盖 lexer / parser / checker / interpreter 的错误流闭环。

## 错误模型

0.0.5 先固定简化版模型：

```txt
T!             Result<T, str>
?              失败就向上传
try/catch      局部处理 Result 的 Err
finally        清理逻辑
fail           主动返回 str 错误
panic          不可恢复运行时错误
```

`try/catch` 不是 JavaScript 异常模型；它只处理 Ku 的可恢复错误。`panic`、数组越界、资源限制等仍然是不可恢复运行时错误。
