# Ku 0.0.19：七语言单轮性能诊断

[English](performance-v0.0.19.en.md) · [公开测量数据](evidence/performance-v0.0.19.json) · [版本限制](v0.0.19-known-issues.md)

**这是一轮严格串行、固定到达率的短测，不是最大容量、七轮正式矩阵或 30 分钟稳定性验收。** 28 个计分窗口合计 583,800／583,800 请求正确，七栈 golden 检查通过。结果描述具体实现及本轮环境，不构成语言的稳定性能排名或生产背书。

## 本轮能说明什么

- 在相同整数计算内核的 HTTP 测试中，Ku 服务 CPU／正确请求为 **2.608 ms**，Rust 为 **3.849 ms**；本轮比值 **0.678**。这是一次固定输入、正常 Release 构建的观测，不是通用提速承诺。
- Ku 的简单响应、JSON、PG 服务 CPU 成本分别为 Rust 的 **1.037、1.260、1.350 倍**；Rust 四项 cgroup 内存中位数均低于 Ku。因此不能宣称 Ku 全面优于 Rust。
- 所有请求正确不等于没有尾刺。Ku JSON 最大 **219.773 ms**、PG 最大 **230.509 ms**；其他栈也有长尾，且 Node PG 客户端记录 p99 为 **236.8 ms**。没有同 RID 的服务端分段或本轮动态采样，唯一根因仍未知。
- 宿主在这轮里确有换入换出；客体未观察到内存限额事件、重大缺页或内存 PSI 增量。这不能证明宿主对尾延迟没有影响，也不能证明 Ku 自身被换出。

## 测试对象与同工边界

候选提交为 `d8c33bca3c629ce82d0d35709c6931f16c86d05b`。Ku 使用 **helpers/text/async/int、正常 Release C11 O2**，不是 direct 或 Fast O3。已核对冻结候选之后 `src`、`crates`、`Cargo.toml`、`Cargo.lock` 和 `build.rs` 未改；后续文档、打包元数据和既有测试合同的变化另计。这份报告仍不代替最终 CI 或安装包验证。

Linux ARM64 虚拟机、Ubuntu 24.04、内核 6.8.0-147-generic；Rust 1.89.0、Clang 18.1.3、Go 1.27.2、Node 24.18.0、Java 25.0.4.1、.NET SDK 10.0.402／运行时 10.0.13、Drogon 1.9.14／JsonCpp 1.9.5。各栈采用各自正常优化构建与 GC/JIT；C++ 是 O3，Ku 是 O2，并未统一优化等级。Java/.NET 的堆上限为服务域的 65%，不等于整个进程上限。

服务域固定 4 核（0–3）／1 GiB，驱动独立 3 核（4–6）／1 GiB，私有 PostgreSQL 独立 1 核（7）／512 MiB。它们仍共用同一虚拟机和物理宿主；限额不是预留的物理内存，不能把客体与宿主内存重复相加。每栈每负载预热 10 秒、计分 30 秒；顺序为 Ku→Go→Rust→Node→Java→.NET→C++，上一栈真实停止后才启动下一栈，不冻结旧服务驻留。

HTTP/1.1 keep-alive，无 TLS、压缩或代理；客户端并发上限 256，连接空闲 500 ms 失效，原计划时点起算的绝对期限 3 秒，无请求重试。

- **CPU**：480/512/544/576 × 1000 次迭代，种子为字符串长度 1/3/7/11；`total=(total*33+i+seed)%100000000`，初值为 seed，核对八位校验输出。边界内整数不溢出。
- **JSON**：固定 1,048 字节对象，解码、counter 由 7 加到 8、构建包含请求 ID 与 data 子树的新 envelope，再编码并校验正文。Ku 的子树读取复制、Rust move、Go/Node 保留引用，所有权工作并非完全相同；Ku text API 与其他栈的 JSON MIME 也不同。
- **PG**：同一 1,024 键数据集、同一参数 SQL、池上限 16，无结果缓存及 SQL 重试。Ku 归还连接执行 `DISCARD ALL`，其他栈采用各自默认 reset；因此数据库列不是等量 reset 工作的对比。

完整算法、语料 SHA 与合同见候选的[测试协议](https://github.com/fengyanweb/ku/tree/d8c33bca3c629ce82d0d35709c6931f16c86d05b/tests/benchmarks/cross_stack/protocol.json)；协议中的七轮/30 秒预热是完整正式矩阵要求，**本次明确采用独立的 10 秒预热单轮计划**。

## 计量口径与结果

CPU 是驱动进程生命周期内的**服务 cgroup CPU 增量／全部正确请求**，包含该窗口启动驱动和完成尾部的服务成本；不包含服务冷启动及最终停止后的成本，也不含驱动、观察器和 PG CPU，不能叫完整服务生命周期成本。PG 服务器成本另在原始记录保留。

p99 是从计划到完整正确响应的**客户端直方图保守桶上界**，包含客户端排队、建连、写读及校验；2.56 ms 以下分辨率 10 µs，高段相对桶宽不超过 0.78125%。它不是排序计算的精确百分位。最大值是实际观测值。内存是到达窗口内 1 Hz 采样、中间 60% 样本的 `memory.current` 中位数，**不是 RSS**；线程为窗口内服务全树采样范围，包含语言运行时及辅助线程。

## 长尾保留与原因边界

下表列出有请求超过 100 ms 的窗口，以及各自最慢正确请求的客户端分段。100 ms 仅用于展示尾刺，**不是统一业务门槛**：本轮协议的 ok/JSON、CPU、PG p99 门槛分别为 100、1000、250 ms。

| 语言／负载 | 最大 ms | 超过 100 ms 数 | 计划→尝试 ms | 尝试→写完 ms | 写完→完成 ms |
| --- | ---: | ---: | ---: | ---: | ---: |
| Ku / json_object | 219.773 | 57 | 42.875 | 0.026 | 176.872 |
| Ku / db | 230.509 | 24 | 0.071 | 14.148 | 216.290 |
| Go / ok | 170.688 | 170 | 10.913 | 18.802 | 140.973 |
| Go / db | 327.339 | 26 | 3.580 | 26.764 | 296.995 |
| Rust / json_object | 126.375 | 6 | 13.516 | 66.070 | 46.788 |
| Rust / db | 375.319 | 37 | 0.663 | 71.105 | 303.551 |
| Node.js / ok | 229.722 | 292 | 55.977 | 101.916 | 71.829 |
| Node.js / db | 445.888 | 120 | 199.220 | 5.278 | 241.390 |
| Java / json_object | 337.436 | 89 | 0.142 | 104.439 | 232.854 |

分段可确认时间花在哪一段，不能说明线程为何停顿。“写完→完成”包含传输、服务、数据库及客户端读取/调度，并非 Ku CPU 时间。例如 Ku JSON 最慢请求复用了连接，仍有 176.872 ms 在写完之后；Ku PG 最慢请求是窗口首个冷连接，建连约 13.780 ms，其余未知，不能直接标为 PG 执行异常。

计费记录还显示：Java JSON 驱动有 213.151 ms cgroup CPU 限流，Node PG 数据库有 26.323 ms；Ku JSON 驱动为 0.044 ms，Ku PG 数据库为 1.106 ms。它们是各窗口内确认发生的事件，未建立逐请求因果，不能用来解释全部长尾。无服务端栈、逐请求阶段和动态热点数据，本轮不据这些结果提出运行时修改。

## 环境：实际换页，不作唯一归因

宿主 16 KiB 页计数在 **18:12:56–18:33:36 UTC** 的内部采样跨度约 1239.7 秒内，换入增加 **208,489 页／3,415,883,776 字节**，换出增加 **208,724 页／3,419,734,016 字节**；不是仅看到已占用 swap。下表包含各栈 golden/预热/计分及收尾阶段内的实际采样跨度：

宿主样本约每 5 秒一次，最大间隔 5.121 秒；按同时段 Unix 时间近似对应客体窗口，未测得两域时间偏差上界，不能进行精确逐请求归因。Pageins 与 swap-in 分别统计，文件缺页不当作交换。

客体在 28 窗资源采样中最低 `MemAvailable` 约 **3147 MiB**、swap 为 0；服务、驱动和 PG 域 `memory.events` 增量均为 0、`pgmajfault` 增量均为 0，服务 memory/io PSI 增量为 0。客体这些计数不能观察宿主换出虚拟机页；也不能由 minor fault 推断交换。1 Hz 资源采样不能排除亚秒停顿。**已确认宿主活动，具体影响大小及每条慢请求原因未知；p99 排名不能外推为稳定排序。**
