# Ku 0.0.19

[English](https://github.com/fengyanweb/ku/blob/v0.0.19/docs/v0.0.19.en.md) · [已知问题](https://github.com/fengyanweb/ku/blob/v0.0.19/docs/v0.0.19-known-issues.md)

0.0.19 是**实验预发行版**，汇集现有运行时、HTTP、数据库和服务管理工作，供受控环境试用。它不是全面生产可用的背书。0.0.x 不承诺源码、生成 C 或内部 Task ABI 向后兼容；升级后应重新构建 native 程序。

## 本版范围

- **native Task**：已实现的有限 async 源码子集、固定容量 driver、期限、取消与清理，以及选定的文件、timer 和网络等待路径。完整 M:N、解释器全面挂起和通用 I/O 覆盖仍未完成，支持范围见[并发合同](https://github.com/fengyanweb/ku/blob/v0.0.19/docs/concurrency.md)。
- **native HTTP**：固定连接归属的多事件循环、HTTP/1.1 连接复用、准入和缓冲预算，以及现有 Task handler 适配。交付已实现的 owner 唤醒、readiness、退役和资源回收修复，不据此承诺所有负载的扩展性或延迟，见[运行时说明](https://github.com/fengyanweb/ku/blob/v0.0.19/docs/multiloop-runtime.md)。
- **PostgreSQL**：native 同步及可恢复的异步连接池路径、有限等待、错误与取消处理及连接指标。已有私有实库样例覆盖读写、中文/null、大结果集、断连和后续请求恢复；结果只适用于各自记录的产物与环境，不代表完整数据库平台矩阵。
- **服务运行**：`ku service` 提供探针、授权状态/指标查询、子进程退出替代和正常停止；部署工具提供摘流、滚动更新、回退及有界监控。`ku supervise` 以完整程序为 worker，执行显式准入、期限和可用平台的资源限制。两者职责不同，见[服务部署](https://github.com/fengyanweb/ku/blob/v0.0.19/deploy/service/README.md)与[进程执行](https://github.com/fengyanweb/ku/blob/v0.0.19/docs/process-execution.md)。
- **JSON**：保留旧默认实现；`json.encode()` / `json.decode()` 复用既有入口。保留 `1e20` 编码后可再次解码的修复，不重新引入 yyjson 默认替换。

数据库操作不自动重试。连接丢失、取消或 worker 终止后，数据库副作用可能未知，不能据退出状态推断事务已回滚。

## 下载与安装

本轮官方包目标如下；以 [GitHub Release](https://github.com/fengyanweb/ku/releases) 实际附件为准：

| 系统 / 架构 | 目标 |
| --- | --- |
| macOS / Apple Silicon ARM64 | `aarch64-apple-darwin` |
| Linux / x64 | `x86_64-unknown-linux-gnu` |
| Windows / x64 | `x86_64-pc-windows-msvc` |

Linux ARM64 用于源码构建的性能与隔离预演环境，**不是本轮第四种官方安装包**。

下载匹配目标的 `ku-v0.0.19-<target>.tar.gz`、清单和 `SHA256SUMS`，先核对校验值，再解压到独立目录。按包内 `README-INSTALL.md` 保留 CLI、伴随库、`deps/` 和 native TLS 文件的布局；VS Code 扩展使用随包 VSIX。运行 `ku version` 核对为 `0.0.19`。native C 构建仍需目标 C 工具链，数据库程序另需对应客户端库；包不包含数据库服务器。

## 验证与发布边界

已有安装、真实服务链路、PG 故障恢复及资源回收结果见[RC 验证汇总](https://github.com/fengyanweb/ku/blob/v0.0.19/docs/production-rc/verification-summary.md)。其中历史 `rc_prepared` 是隔离样例的准备状态，没有真实应用灰度，不能当作 0.0.19 最终产物或生产验收结果。

2026-10-28 最后一次有效、无 perf/探针的短复核中，取消阶段 60,000 个短请求全部正确，p99 **1.557 ms**，但最大值 **98.809 ms**，仍有 169 个请求超过 20 ms。过载后恢复也保留了尾刺；历史正式窗口失败未被覆盖。五个候选窗口和正式 30 分钟验收仍未完成。

本轮完成了 Ku、Go、Rust、Node、Java、.NET、C++ 的一次串行固定负载对比：28 个测量窗口、583,800 个正确请求。CPU、JSON 和数据库的相对表现不同；宿主实际换页及长尾请求保留在[双语性能报告](https://github.com/fengyanweb/ku/blob/v0.0.19/docs/performance-v0.0.19.md)中。这是有边界的最新对比，不是最大容量或长期稳定性验收。

本次最终提交、标签、安装包与必要 CI 的实际结果由 Release 正文及资产清单给出；本文不预先把它们记为通过，历史 HTTP 504、两个暂停项及资源保证见[已知问题](https://github.com/fengyanweb/ku/blob/v0.0.19/docs/v0.0.19-known-issues.md)。官网本轮只更新代码并打包，未部署。
