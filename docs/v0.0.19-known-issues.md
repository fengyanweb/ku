# Ku 0.0.19 已知问题

[English](v0.0.19-known-issues.en.md) · [版本说明](v0.0.19.md)

0.0.19 是实验预发行版。本页保留已确认的限制与未解释的失败，不把历史检查、短测或隔离样例外推为全面生产保证。

## 延迟与稳定性

- **历史 HTTP 504：原因未确认。** 历史出现过，本轮短复核没有唯一还原；最早三个 504 证据不足。它们没有被标记为已修复，正式 30 分钟长期验收尚未通过，不再追加无目标的历史追查。
- **取消阶段 p99 通过短测，低频尾刺仍在。** 最后一次有效短序列为正常 30 秒 → 过载 3 秒 → 恢复 15 秒 → 取消 30 秒 → 恢复 10 秒。取消阶段 60,000 个短请求全部正确，精确 p99 为 1.557 ms，最大 98.809 ms；169 个超过 20 ms。过载后恢复 p99 为 1.606 ms、最大 54.246 ms，74 个超过 20 ms；取消后恢复 p99 为 1.420 ms、最大 3.751 ms。
- 上述取消长尾集中在一簇，既包含客户端生成/交接延迟，也包含首次写入后的时间；缺少同 RID 的完整服务端拆分，不能全部计作 Ku 执行。正常窗口也曾出现长尾，尚未确认取消代码或宿主是唯一原因。原 378 条慢请求属于同一窗口的成簇观测，不是 378 次独立故障。
- 前两次复核遇到其他项目负载及换页，生成 p99 超过 5 ms，不能用作合格的服务 SLO 测量。最后有效窗口未观察到已识别的其他项目构建/测试，但不等于整机绝对空闲。短测没有重测真实取消停止/物理回收时间；刻意过载的拒绝、超时及其他 HTTP 错误继续单列。
- 历史 phase4 的 p99 25.761695 ms 失败仍保留；五个候选窗口和 1800 秒正式验收仍未执行。按当前决定暂不继续追低频尾刺，不延长期限、不降低检查频率，也没有加入推测性的运行时补丁。

最后有效取消复核基于运行时代码 `418de2a`；正常服务二进制 SHA256 为 `5d337c2ef159e5d21a44ca2eb3ccab50f2fc0e9128a583b50abe88c67eb36ffc`。这是历史测量身份，不代替本次最终 Release 的产物身份。

## 功能与资源边界

| 项目 | 当前边界 |
| --- | --- |
| Task 与后端 | native C 只支持明确列出的 async 子集；完整 M:N、解释器全面挂起、通用网络等待及全部阻塞库接入未完成。静态检查成功不表示所有后端均可执行，详见[并发合同](concurrency.md)。 |
| 两个暂停项 | 通用值复制/释放与 AST 后续分析继续暂停。已修具体调用/清理路径不等于所有深度与函数图都已覆盖。 |
| JSON | 保留旧默认与共用接口；大浮点往返修复保留。`1.0`、`-0.0` 等不保证保留原浮点类型标签或负零符号；整数溢出仍拒绝。yyjson 替换和性能探索已结束。 |
| PG 与其他数据库 | 已有实库结果不是完整平台矩阵。池拒绝、超时和结果未知必须区分；数据库不自动重试，worker 终止不证明回滚。 |
| 服务恢复 | 同宿主多实例、进程替代与样例回退不等于节点级高可用、真实生产灰度或数据回滚。真实应用、目标 SLO 和生产回退对象仍需各自验收。 |
| 资源计量 | Task/HTTP 容量账本不等于进程 RSS。单 Task 全堆、共享池、缓存与外部库内存没有逐 Task 精确拆分。有限观察无持续增长不等于全项目无泄漏。 |

`ku supervise` 的 Linux 硬限制需要可写、已委托且满足 `memory`、`pids`、`cgroup.kill` 等条件的 cgroup v2；约束的是内核计费量，不能承诺每个瞬间 RSS 绝不越界。Windows 使用 Job 提交内存限制，指标与 RSS/Linux 计费量不同；内存不足不保证都变成普通 Result。macOS 原生明确拒绝该隔离模式，普通执行与普通 `ku service` 仍可用。

`ku supervise` 不自行给协调器设置 OS 硬限制；worker 限额也不自动覆盖外部数据库、构建器或宿主。外部整单元限制须单独配置和验证，不能宣称整个系统内存绝对封顶。已有 36 次超限回收结果按原身份保留，本轮没有无故重跑，也不将其充作 HTTP 长期验收。详见[进程执行](process-execution.md)。

官方包目标只有 macOS ARM64、Linux x64 和 Windows x64；Linux ARM64 的源码构建性能环境不属于这三种安装包。历史 RC 隔离预演与新版本最终 CI/安装包验证分别记账，发布任务跳过不算发布成功。本轮七语言固定负载短测已完成，完整容量与长期矩阵未执行，官网只更新代码和打包，未部署。
