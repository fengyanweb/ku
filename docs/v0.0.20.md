# Ku 0.0.20

Ku 0.0.20 汇总 0.0.19 之后已采用的运行时修复、CLI／SDK 和编辑器改进。解释器、静态检查、原生 C 后端与官方标准库继续提供各自已实现的能力。

## 主要变化

- HTTP：修复处理器越过请求绝对期限及未读取请求参数时的入口问题；已证明有界的同步 JSON 处理可使用现有 HTTP owner，其他情况保留 worker 回退。
- Task 与 JSON：修复 Task 字符串比较和相关值传递、结果处理与资源计费问题；补齐受支持 Task JSON 路径。JSON 保留原默认引擎。
- PostgreSQL：修复等待队列公平性和空闲连接并行使用问题，保留结果所有权、严格连接清理及业务 SQL 不自动重试的行为。
- CLI 与 SDK：完善常用命令简写、独立安装后的 SDK 定位、编译器身份检查和打包完整性，避免从开发机绝对路径加载运行时库。
- VS Code：修复可执行文件查找、格式化、导入补全和文档失效时的检查队列处理；插件由本版源码重新构建。

## 安装与升级

从 [v0.0.20 Release](https://github.com/fengyanweb/ku/releases/tag/v0.0.20) 下载与平台匹配的包，核对 `SHA256SUMS` 后解压；CLI、`libku.rlib`、依赖、元数据和目标 native/TLS pack 必须成套保留。

发行目标为 macOS Apple Silicon（aarch64）、Linux x86_64 GNU 和 Windows x86_64 MSVC。未提供的架构不代表已有对应安装包。

- `ku -v`／`ku --version` 输出 `0.0.20`。
- `ku run` 和 `ku check` 不要求安装 Rust。
- 默认 Runner `ku build` 使用随包 SDK，需要匹配元数据中完整编译器身份的 Rust **1.99.1** 和系统链接器。相同主次版本或仅修改工具链标签不能保证 rlib 兼容。
- `ku build --backend c` 需要目标 C 工具链，以及程序使用的数据库、TLS 等原生依赖；缺少依赖时应按报错补齐。

旧版本安装可以保留，升级时切换整套目录及 PATH，不把新 CLI 与旧 SDK 混用。细节见 [CLI／SDK 文档](cli-runtime-bundle.md)。

## 适用范围

本次是正式发行整理，不是新的跨语言性能排名或完整生产稳定性结论。HTTP／PG CPU 和固定内存等研究目标仍有未完成项；结构上减少工作不等于已证明整服务提速，空闲内存回落也不等于稳态或峰值下降。

不同后端支持范围仍有差异。平台资源限制、长尾／超时及数据库取消边界见 [已知问题](v0.0.20-known-issues.md)。历史 [0.0.19 性能记录](performance-v0.0.19.md) 保留原身份，不改写成本版成绩。
