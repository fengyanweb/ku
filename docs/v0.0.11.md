# Ku 0.0.11

0.0.11 继续把 native 和 package 的前置链条做实：Result 不再只是解释器语义，已经进入 IR 和 native C 子集；package 也不再只是本地 import root，开始支持可缓存、可校验的 file dependency。

## 已完成

- 固定第一批 Result ABI：native C 后端支持 `Result<int|bool|str, str>`，能生成 `{ ok, value, error }` 结构体、`ok` / `err`、`?` 分支、`BindOk` 取值和错误传播返回。
- `try/catch/finally` 的 IR lowering 增加错误 CFG 边：try 或 catch 里出现 `?` / `fail` 失败时，会进入 finally error block，执行 finally 后继续传播错误。
- package 支持 `dep.<name>`、`dep.<name>.source`、`dep.<name>.checksum`，当前 source 支持 `file://` 目录。
- dependency 会缓存到 `<package>/.ku/cache/packages/<name>/<version>/`，`ku.lock` 会记录 package dependency、source、checksum 和 cache path；无 checksum 的 file dependency 会在 source 内容变化后刷新 cache。
- 新增 `ku package gc <file.ku>`，按 `<name>/<version>` 清理 manifest 当前依赖之外的缓存版本。
- 修正 match guard 诊断：`_ if (...)` 不再让后续分支误判不可达，也不计入 enum 穷尽覆盖。
- 新增重复未带 guard 字面量分支诊断，避免明显不可达分支被放过。
- 补充 Result native、package dependency、checksum mismatch、cache GC、match guard 的回归测试。

## 当前边界

- native C Result ABI 只覆盖 `int` / `bool` / `str` payload，错误 payload 固定为 `str`。
- native C 后端仍是 prototype，只覆盖基础值、局部变量、直接函数调用、`print`、`return`、`if`、`while` 和基础 Result。数组、struct、enum、闭包、match、try/catch native lowering 仍会明确报不支持。
- `try/catch/finally` 的解释器语义可用；IR 已有错误边，但 return 穿过 finally 的延迟返回和 native C catch error slot 还没有完成，因此 try/catch native 仍未开放。
- package 当前只支持 `file://` source。HTTP/registry、网络下载、真正语义版本求解、强校验和下载重试策略还没有实现。
- match 仍未实现复杂嵌套模式矩阵、guard 穷尽性证明和完整不可达分支证明。
- async / await 和 LLVM 后端没有进入 0.0.11。

## 验证重点

```powershell
cargo test --no-fail-fast
cargo clippy --all-targets -- -D warnings
cargo build --release
.\release\ku.exe version
.\release\ku.exe -h
.\release\ku.exe run .\examples\hello.ku
.\scripts\archive-release.ps1 -CheckOnly -SkipBuild
```

## 下一步

1. 给 native try/catch 增加显式 error slot 或 block parameter，让 `BindError` 能拿到具体错误值。
2. 固定闭包 ABI，拆清捕获值、引用捕获和 async 边界的所有权模型。
3. 扩展 native C 到 struct / enum / array / string ABI。
4. 把 package 从 `file://` 推进到 registry 草案、版本求解、下载校验和缓存淘汰策略。
5. 在 checker 上实现嵌套模式矩阵、match guard 和更完整的穷尽性检查。
