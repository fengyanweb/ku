# Ku 0.0.15

0.0.15 的重点是清掉 HTTP 旧兼容债、补对象解构赋值、同步最新示例，并把 `.clone()` / native ABI / IR 优化路线写清楚。

## 语言语法

- 新增对象解构赋值：`{ name, field: local, missing = fallback, ...rest } = object`。解构会消费右侧 object；需要保留原对象时显式写 `object.clone()`。
- 支持 `{ code } = http` 从 std.http 模块对象读取可作为值使用的成员。
- 静态 object 缺字段在 checker 阶段报错；动态 object 缺字段在运行时报错。需要宽松读取时继续使用 `object["field"]?`。
- 新增 `object.get_or(obj, key, default)` 和 `obj.get_or(key, default)`；default 立即求值，静态字面量 key 会尽量保留字段类型。
- 新增函数类型语法 `fn(int, int): int` 和 `async fn(int): str!`；箭头函数类型写法 `(int, int) => int` 不作为类型使用。
- 修复 parser 跨行误吞结构体字面量：`Ident { ... }` / `ns.Type { ... }` 的 `{` 必须和类型名在同一行。

## HTTP

- `http.service` / `http.server` 属性式默认对象已移除。
- 必须写 `http.service()` / `http.server(config)`；错误诊断会提示标准写法。
- 普通 route handler 改为 Return 模型：不读取请求时写 `fn()`，读取请求时写 `fn(req)`；保留 `_req` 给适配器/测试 mock 等必须带参数但暂时不用的场景；不允许第二个 `res/writer` 参数。
- handler 必须返回 `{ status, headers, body }` 或 `{ status, headers, body }!`，普通响应通过 `return http.text/json/html/empty/redirect(...)`。
- `service.get/post/put/del(path, handler)` 保持唯一写法；`del` 对应 HTTP `DELETE`，不新增 `delete` 别名。
- writer 保留给后续 `http.stream(...)` 专用 API，不作为普通 handler 参数暴露。
- route、bind、listen、资源限制和压测脚本保持不变。

## 示例与插件

- `examples/index.ku` 改为可 `ku check` / `ku run` 的最新语法索引示例。
- `examples/object.ku` 覆盖严格索引、可选索引和对象解构。
- `examples/loop.ku` / `examples/control_flow.ku` 覆盖 `for i in 10`、单语句 body、`break/continue` 和 `++`。
- 清理 `examples/.ku` 与 `examples/package/.ku` 生成目录。
- VS Code 插件版本升到 `0.0.15`，`http.service` / `http.server` 不再作为全局纯文本补全暴露；成员补全插入函数调用形式，并新增对象解构 snippet。
- VS Code completion/hover 同步 `object.get_or`、`std.object`、`http.html` 和 0/1 参数 HTTP handler 模板。

## Native / IR 路线

- `.clone()` 深拷贝规则已写入 `docs/syntax.md`：Copy clone 消除，Owned 递归 clone，Task 禁 clone。
- unused import 默认报 `E0901`；`ku check --deny-unused` 增加严格 unused 本地绑定检查：本文件局部变量/常量未读取时报 `E0905`，`_` / `_name` 表示有意丢弃。
- registry 增加 Ed25519 detached signature verifier；未配置 source/verifier 时继续 fail-closed，不能读旧 cache 绕过信任。
- registry 远程 archive 固定为 `.tar.zst`，下载上限 32 MB，并新增受限解包校验：单根目录、必须含 `ku.mod`、拒绝路径逃逸和链接/特殊文件、限制总大小/文件数/单文件大小。
- `ku build --target` 增加第一阶段 resolver：`host`、`x86_64-linux`、`x86_64-windows`、`aarch64-darwin`；target 字符串拒绝路径逃逸，C compiler 查找顺序同步为 `KU_CC -> zig cc -> clang -> cc -> gcc`。
- native C 在正式 `KuString` lowering 前明确拒绝字符串拼接，不生成错误 C。
- IR 优化第一阶段已接入输出路径：整数/布尔常量折叠、常量分支折叠和不可达 block 删除。后续简单内联、临时变量消除、drop/clone 消除、escape analysis、stack allocation、monomorphization 和 bounds check 优化继续按 `docs/ir.md` 推进。
- native closure、正式 `KuString`、native dynamic object、registry 根公钥/轮换/吊销/受限解包、最终 native binary build 和 native async 仍按 `docs/roadmap-decisions.md` 的顺序推进。
