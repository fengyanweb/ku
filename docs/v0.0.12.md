# Ku 0.0.12

0.0.12 继续补 0.0.x 的语言闭环，重点不是扩大口号，而是把已经暴露给用户的语义做稳：`match` 支持递归 payload 模式，HTTP 作为独立标准库模块进入语言，native C 输出开始生成真正的系统入口 wrapper。

## 已完成

- `match` 模式从“payload 绑定名列表”升级为递归模式树；`switch` 旧别名不再支持。
- enum payload 模式支持嵌套 enum variant、字面量、`_` 和绑定名，例如 `Expr.Box(Inner.Number(n))`。
- checker 会递归检查模式类型，并把绑定名按 payload 类型放入 arm 作用域。
- enum 穷尽性不再把 `Expr.Box(Inner.Number(n))` 误判为覆盖整个 `Expr.Box(_)`。
- 重复的未带 guard 嵌套模式会诊断为不可达；未带 guard 的完整 variant 捕获后，后续同 variant 分支也会诊断不可达。
- namespace import 的 enum match pattern 重写改成递归处理，避免嵌套模式漏重写。
- 新增 `std.http` 标准库模块，必须写 `import "std.http"` 或 `import http from "std.http"` 后才能使用。
- 新增 `http.get(url): HttpResponse!`、`http.post(url, body): HttpResponse!`、`http.request(config): HttpResponse!`，支持 `http://` 和 `https://`。
- HTTP response 使用对象表示：`{ status, headers, body }`。网络、协议、URL 和 body 限制错误返回结构化 `Err({ domain, code, message })`，不做自动重试。
- `http.client(config?)`、`http.service(config?)`、`http.server(config?)` 支持第一版配置对象。
- HTTP server 已有第一版阻塞 runtime：`bind()` 会真实绑定端口并编译运行时路由表，`listen()` / `listener.run()` 会处理基础 HTTP 请求，`listener.close()?` 可显式关闭未运行的 listener。
- HTTP route handler 固定 `(req, res)`，checker 会复查请求对象字段、返回 `{ status, headers, body }`，并禁止修改外层捕获变量。
- HTTP server 当前覆盖 200、404、405、400、413、431 等基础 wire-level 响应路径。
- 新增 `std.config`，必须显式导入；支持 `config.env()`、`config.env_file(path)` 和平面 `config.yaml(path)?`。
- 新增 `fs.write(path, text)` 和 `fs.try_write(path, text)`。
- `fs.try_*`、`json.try_parse`、`array.try_get`、`string.slice`、`http.*`、`err()` 和 `fail` 的可恢复错误统一为 Error 对象 `{ domain, code, message }`；`catch (err)` 中 `err` 不再按 `str` 检查。
- 新增泛型函数语法 `fn id<T>(value:T): T`，调用处按实参推断泛型。
- 新增 string / array 标准库实例方法调用，例如 `text.trim()`、`values.try_get(0)?`。
- 对象支持字符串键动态索引和赋值；字符串支持 `int` 索引返回单字符 `str`。
- 对象索引改为严格语义：`object[key]` 缺键直接报错，只有 `object[key]?` 显式允许缺失并返回 `null`。
- 箭头函数支持参数类型和返回类型，例如 `(a:int, b:int): int => a + b`；函数值仍是一等值，可以赋给其他变量后调用。
- `async fn` / `await` 已完成真实 AST、checker 和解释器 runtime：调用立即启动 task，同一函数可启动多个 task，`await` 只能在 async 函数内，`await task?` 等价于 `(await task)?`。
- async 函数第一版必须显式返回 `T!`；task 可读取但不能修改外层捕获，checker 和 runtime 双重拒绝捕获写入。
- async runtime 默认 `max_tasks=1024`；blocking worker 为 `min(32, max(4, CPU 核心数))`，blocking queue 为 1024。超限返回 `task/too_many_tasks` 或 `task/queue_full`，不 panic、不无限重试。
- async task 内的 fs/config/http 阻塞调用进入 blocking pool；self-await 和 await cycle 会有界失败，不永久死等。
- `ku check --json` 已提供 JSON Lines diagnostics；VS Code 使用 JSON 优先并保留单次文本回退。
- `ku llvm file.ku` 已提供文本 `.ll` 最小后端，覆盖基础类型、普通函数、局部变量、直接调用、`return`、`if/while` 和 `print`。
- native C 已支持 struct layout/字面量/字段读写、带长度 array 与越界检查、enum tag/payload 和 match lowering；递归值布局仍明确拒绝。
- registry manifest 和 lockfile 离线 schema/parser 已实现，严格检查 semver、必填字段、URL 和 `sha256-*`；resolver 支持精确版本和 caret 范围。
- `if` / `while` / match guard 条件改回严格 `bool`，不再使用 truthy 规则。
- CLI 运行解释器时使用固定栈大小的解释器线程，避免 Windows debug 构建中递归示例过早触发宿主线程 stack overflow；Ku 自身的最大调用深度保护仍保留。
- native C 输出把 Ku 的 `main` 改名为 `ku_main`，并生成 `int main(void)` wrapper；Result main 返回 Err 时打印错误并返回非 0。
- VS Code formatter 已支持 4 空格缩进、连续空行压缩、运算符/逗号空格和 `} else` / `} catch` / `} finally` 合并。

## 仍未完成

- LLVM 仍是文本小子集后端，已支持非递归 struct 和基础/struct Result；尚不支持数组、enum、闭包、HTTP 和 async。
- registry 网络下载和实际缓存更新还没有实现。当前可执行 dependency 仍是 `file://` 和 `ku-fnv64-*` 内容校验。
- 完整 native C 后端仍未完成。当前仍明确拒绝闭包、try/catch/finally 和 async lowering，array 的正式释放/所有权 ABI 也尚未固定。

## 0.0.12 后续补齐

- native C 已继续完成带长度 array runtime、读写越界检查、enum tag/payload 和 unit/payload/嵌套 match lowering。
- LLVM 文本后端已扩展非递归 struct、字段读写和 `Result<int|bool|str|struct>`；array、enum、闭包和 async 仍明确拒绝。
- registry resolver 已支持精确版本与 caret 范围、最高兼容版本选择和冲突检测；实际网络下载仍未接入，但重试、超时、下载大小、临时 cache 和原子替换策略已经有界。
- async task 已增加 `status()`、`cancel()` 和 `await_timeout(ms)`；取消为协作式，等待超时不会隐式取消目标任务，native async lowering 继续拒绝。
- native array 的正式 copy/move/drop 所有权、统一 Error ABI、try/catch/finally、闭包和 registry 网络协议仍是后续阶段。
- match guard 的完整模式矩阵和跨 guard 的穷尽性证明还没有完成；当前 guard 分支仍不计入穷尽覆盖。
