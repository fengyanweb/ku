# Ku 0.0.17

0.0.17 固定同步 `&` 只读借用的首版实验合同，并在 Ku 自举 Parser 子集中增加 braced `while`。Ku 仍处于实验阶段，不可用于生产；0.0.x 不承诺源码或生成 C/FFI ABI 向后兼容。本次发布不新增开源许可证，编辑器扩展继续保持 `UNLICENSED`。

## 同步只读借用

参数写 `&name: T`，调用仍写 `Read(value)`；函数类型使用 `fn(&T): R`。普通 owned 参数继续默认 move，独立副本仍需显式 `.clone()`。不引入普通 `&T` 类型、地址运算、可变借用、生命周期或用户可见 `view` / `ref` 别名。

- Rust 与 Ku Lexer 同步新增 `Ampersand`，共 73 种 token；`&&` 保持最长匹配。
- 命名、局部、匿名、带括号箭头函数和函数类型保存参数模式；namespace/import 重写保留模式。checker 检查修改、owned 移出、存储/返回/捕获逃逸、async 边界及同调用 borrow/move/mutation 冲突；E0910–E0919 固定位置与修复帮助，文本和 JSON Lines 均有测试。
- 解释器使用同步调用期 owner guard 和只读弱视图，嵌套投影不深拷贝来源；线程/task 与存储边界另有防御性检查。IR verifier 在 lowering 和 C backend 入口检查模式及来源，优化后不能擦除借用合同。
- C 对透明 non-Copy 参数使用 `const` 指针，callee 不 drop borrowed 参数；caller 保存新建临时 owner，并在调用结束或异常展开时清理。typed function invoke ABI 保留 owned/borrowed 差异；相关生成 C/FFI 产物必须重编译。
- 首批只读 stdlib 路径包括 `len/str/print/println`、字符串长度/只读比较、数组长度/判空和 `json.stringify`。JSON typed array 复用只读 writer，不为输入装箱或取得其所有权；输出仍正常分配。

首版明确拒绝无括号借用箭头、async borrowed 参数、borrowed `for`、borrowed match 的 owned payload binding、fallible object lookup、消费式解构、borrowed Result `?` 和未迁移 stdlib 路径。适用时先显式 clone。LLVM 文本后端不支持借用，native async ABI 仍未实现；struct 函数字段仅保留 IR 模式，C 字段布局尚不支持，函数数组调用则已有 native 覆盖。

## 自举 Parser：有界 while 切片

Stage3 在现有 module/import/struct/enum、基础函数/语句和 braced `if` 上增加 `while (condition) { ... }`。`While` 的 children 固定为 condition 与源码顺序 body statements，使用后序 NodeId；if/while 共用 32 层显式栈和每函数 128 条聚合 statement 上限。

新增 Unicode/CRLF 静态 golden、解释器/Rust canonical 差分、32/33 层及 128/129 条边界、混合 if/while transport 和源码删除后的 native 验收。解释器用独立 while/token-map 边界批次，保留每个子进程 30 秒 watchdog，没有通过延长 timeout 掩盖工作量。分配测试覆盖 16/32 层嵌套以及 32/64 条 statement 的成功/失败清理；IR 门槛确认增长表复用 append，防止重复克隆整表。

这不是完整 Ku Parser：`&` 参数模式、函数类型、泛型、async、for/try 及其余表达式仍待迁移。Diagnostic 当前仍经 `Error.message` 传递 canonical 文本，跨 checker/CLI/编辑器的 typed transport 尚未闭环。Rust 仍承担 bootstrap compiler、依赖图加载、checker、IR 和 backend。

## 测试工具与实际证据

断开 stdout 的 registry 管理测试在 Unix 使用本地 socket pair，并显式关闭本端写方向，稳定触发写失败；非 Unix 路径继续使用关闭读端的 pipe。Unix 测试不再依赖对端关闭何时被观察到，并验证对端和写端的存活副本也不能恢复写入。此改动属于测试工具，不代表增加了新的数据库或 registry 业务能力。

发布脚本补齐普通 `ku build` 所需的完整 Rust 运行器编译依赖，不再只携带 `libku.rlib`；`deps/` 包含同次私有构建的 RLIB 及匹配平台的 proc-macro 动态库，并核对文件集、大小、hash 和对象格式。独立 consumer 隔离开发搜索环境，验证隐藏依赖时构建失败、恢复依赖时带本地 import 的默认 build 成功并在源码保留时运行，隐藏编译依赖后仍可运行；无 import 的独立 runner 另行验证移走源码后运行。默认 runner 只嵌入主文件，含 import 时仍需要原导入源码；完整 import graph 的源码无关部署使用 `ku build --native`。这些测试与已有 native TLS consumer 分开验收，实际执行结果仍须以对应提交的发布合同门禁为准。

发布前基线 [`11c566b`](https://github.com/fengyanweb/ku/commit/11c566b) 已通过 Windows/Linux/macOS CI。此前本机完整 workspace 回归及借用专项也已执行：Lexer 2、Parser 11、checker 20、interpreter 5、native 6、allocation 1；Windows MSVC ASan 覆盖 native/allocation。0.0.17 以 `v0.0.17` tag 同一提交的实际三系统 CI 结果为准，不沿用旧提交；最终 CI 链接见 [Release 正文](https://github.com/fengyanweb/ku/releases/tag/v0.0.17)。

借用分配 fixture 对 16B/64KiB 输入执行 512 次嵌套读取，新增分配为零；显式 clone 为正对照。普通/投影临时值、后续参数 `?` 中断在 1/256 轮下保持相同峰值，并在 catch/finally 入口核对清理；三个确定性 timeout 点和 JSON 输出 OOM 另检查来源完整、调用次数与状态恢复。这些是有限 fixture 的证据，不是全进程 RSS、固定硬件生产吞吐、长期 soak 或穷尽内存安全证明。

新版本门禁包括 Rust fmt/check/clippy、完整 workspace、编辑器测试、三系统 native/source-free 验收、release 脚本 `SelfTest` / `CheckOnly` 以及独立 Linux ASan/UBSan/leak job。最终结果以新版本提交对应的实际 CI 为准，job 存在不等于通过。

## 发布与仍未完成的边界

- 每个操作系统/CPU 独立构建 `ku-v0.0.17-<Rust triple>.tar.gz`；没有 Windows/Linux/macOS 通用单一二进制。外层资产包含 `README-INSTALL.md`、`RELEASE.json`、`SHA256SUMS` 与第三方 notices，并列 manifest 记录归档及文件 hash。内部 bundle 的 `deps/` 携带 RLIB 与匹配平台的 proc-macro 动态库，不包含 `ku-registry` 服务端。安装包以 GitHub Release 实际列出的 target 资产为准，`native_ci-*` 只是测试样例。打包/归档与编译工具链要求见 [history.md](history.md)。
- 数据库继续只有 `module.client(config)?`，不新增 raw/pool 兼容入口。驱动仍是 native-only；Redis 新 client 与 MySQL/MariaDB 实服复验、PG Linux/macOS 实库查询仍未完成，fake ABI、链接或启动门槛不替代真实服务。
- Redis TLS、通用 bytes/net 复用、跨 Oracle/MariaDB 的一致证书验证、transaction/exclusive 和 typed SQL 输入仍是既有边界。PG SQL 预检也不能完整证明任意 SQL 的 session purity。详细安全合同保留在 [0.0.16 记录](v0.0.16.md)。
- 完整自举、生产 soak、固定硬件高并发基准和官方托管 registry 高可用未完成；本次发布不把这些列为成果。

下一步先完成新版本发布验收，再逐个推进 Parser 剩余切片与既有协议边界；每一步保持诊断、所有权、差分和资源门槛。
