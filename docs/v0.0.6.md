# Ku v0.0.6 记录

## 已完成

- 解释器版本同步到 `ku 0.0.6`。
- Rust 源码开始按职责拆分：
  - `src/lexer/mod.rs`
  - `src/parser/mod.rs`
  - `src/checker/mod.rs`
  - `src/runtime/interpreter.rs`
  - `src/runtime/value.rs`
  - `src/stdlib/*`
- 新增 `stdlib` 运行时分发层，内置能力从解释器主体中迁出。
- 新增标准库模块：
  - `string.len/contains/starts_with/ends_with/trim/lower/upper/replace`
  - `array.len/is_empty/push/concat/first/last`
  - `json.parse/try_parse/stringify`
  - `time.now/unix/millis`
- `ku check` 同步检查 stdlib 参数数量、基础类型和数组元素类型。
- 新增 `examples/stdlib.ku`。
- 新增 `tests/language_v006_stdlib_test.rs`，覆盖 stdlib happy path、类型错误、模块遮蔽、JSON Result 和运行时错误。

## 没有假装完成

- 包管理还没有做。原因：需要先固定 package/module 边界、版本解析、缓存目录、循环依赖策略。
- async / await 还没有做。原因：需要任务模型、事件循环和阻塞 stdlib 的边界，不能只加关键字。
- native C / LLVM 后端还没有做。原因：需要 IR、类型布局、运行时 ABI 和标准库 ABI。
- 引用捕获闭包还没有做。原因：会改变 `Env` / `Value` 所有权模型，必须单独设计。
- 复杂嵌套模式和 match 穷尽性检查还没有做。原因：需要完整类型信息和模式矩阵。

## 下一步建议

1. 继续拆分 checker，把 stdlib 类型签名从 `checker/mod.rs` 中抽到 `stdlib` metadata。
2. 做 `array.try_get`、`string.slice`，并配合 `?` 闭环。
3. 固定 package 草案：`ku.mod` / package name / import root / cache。
4. 设计 native 后端前先做中间表示 IR，不直接跳 C/LLVM。
5. 做 release history 自动化，避免每次手工复制解释器。
