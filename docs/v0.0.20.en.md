# Ku 0.0.20

Ku 0.0.20 brings together adopted runtime fixes and CLI, SDK and editor improvements since 0.0.19. The interpreter, static checker, native C backend and standard library retain their implemented capabilities.

## Changes

- HTTP: fixed absolute handler-deadline and unused-request-parameter entry cases. Proven bounded synchronous JSON handlers can use the existing HTTP owner; other cases retain the worker fallback.
- Task and JSON: fixed Task string comparison and related value transfer, result handling and resource accounting; completed supported Task JSON paths. The original default JSON engine remains in use.
- PostgreSQL: fixed wait-queue fairness and parallel use of idle connections while preserving owned results, strict connection cleanup and no automatic business-SQL retries.
- CLI and SDK: improved command aliases, SDK discovery outside a source checkout, compiler identity checks and package completeness, avoiding runtime-library references to developer-machine absolute paths.
- VS Code: repaired executable discovery, formatting, import completion and diagnostic queue invalidation. The extension is rebuilt from this release's source.

## Install and upgrade

Download a matching bundle from the [v0.0.20 Release](https://github.com/fengyanweb/ku/releases/tag/v0.0.20), verify `SHA256SUMS`, and extract it. Keep the CLI, `libku.rlib`, dependencies, metadata and target native/TLS pack together.

Release targets are Apple Silicon macOS (aarch64), GNU Linux x86_64 and MSVC Windows x86_64. This release is validated on macOS 15, Ubuntu 24.04 and Windows Server 2025; other OS versions have not each been exercised. Other architectures do not have an implied installer.

- `ku -v` / `ku --version` prints `0.0.20`.
- `ku run` and `ku check` do not require Rust.
- Default Runner `ku build` requires Rust **1.99.1** with the exact compiler identity recorded by its SDK, plus a system linker. Matching only a major/minor version or changing a toolchain label does not make an rlib compatible.
- `ku build --backend c` needs a target C toolchain and the native database/TLS libraries used by the program. Follow missing-dependency diagnostics.

Keep older installations if needed; switch an entire bundle and PATH when upgrading. Do not mix a new CLI with an older SDK. See [CLI/SDK compatibility](cli-runtime-bundle.en.md).

## Scope

This formal release does not establish a new cross-language performance ranking or complete production-stability acceptance. HTTP/PG CPU and fixed-memory research targets remain open. Removing structural work does not prove whole-service acceleration, and idle-memory recovery does not establish steady-state or peak reduction.

Backend coverage differs. See [known limitations](v0.0.20-known-issues.en.md) for resource limits, latency/timeouts and database cancellation boundaries. The [0.0.19 performance record](performance-v0.0.19.en.md) retains its original identity.
