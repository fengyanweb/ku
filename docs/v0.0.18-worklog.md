### 已发现的具体缺陷和漂移

1. `src/ir/mod.rs` 将泛型 `T` 降为 `Named("T")`，checker 调用推断没有保留为实例计划。
   `Read<T>` 对 str/int 的 check/run 成功不能证明 native 可运行。
2. `is_owned_type(Generic)` 返回 false，需要以具体 owned 实参复检函数体；
   类型替换还缺函数类型递归；import 类型重写可能覆盖同名泛型参数。
3. 解释器 `Stmt::Try` 用 `?` 接收 body/catch 的 Rust 错误，绕过 finally。
   cancel/timeout 清理优先级需要明确合同，不能仅删除 `?` 后取消清理超时。
4. 编辑器把 scalar 列直接当成 UTF-16 列，非 BMP 字符之后诊断错位。
5. Ku Stage3 Parser 仅接受 Ident 参数、Parameter mode 写死 0。
6. 协议文档仍保留 TLS pack 三系统待绿的旧状态；默认 runner 的 import 源码依赖
   仍存在，不应只称为历史限制。
7. 现有 HTTP benchmark 保存每次请求延迟，内存随总请求量增长，不能用作正式 soak 框架。

## 方案与回滚边界

方案 A：复用 checker 类型推断与具体 ABI，生成有界单态实例计划；在现有 IR 中增加
显式挂起点和生命周期验证，复用 Result/Error/drop、TLS 状态机和协议解析。
优点是保留单一类型与调用语义；缺点是必须补完整数据流和资源账本。

方案 B：为泛型加动态分派，或把 async 包装成更多同步线程。
它能减少初始改动，但改变 native 泛型合同或保留 I/O 占 worker 的根因，不能满足任务书。

采用 A。每一切片独立测试、可回滚；没有完整验收前不创建 v0.0.18 tag。

### 已修复的实际问题

- Task owning 读取以前只 clone Rust handle，来源未清空，scope 也没有清理责任。
  现在真正 move Task 或含 Task 的选中字段，调用方、被调方、返回值和匹配分支按当前
  owner 清理；只读捕获、同步借用和 match guard 的候选绑定不获得清理责任。
  match 选中后才提交 payload move，wildcard 未消费任务在表达式返回前清理；
  guard 消费候选 Task 报 E0805，guard 自己新建的 Task 不受此限制。
- 只读闭包共享绑定曾使已完成、未 await 的结果在原 scope 退出后继续存活。
  scope 现在显式释放结果所有权，观察句柄可保留标识控制块，不能保留 awaitable payload；
  迟到完成也检查 owner 已释放标记。Task 仍不可 clone，不新增用户状态/取消接口。
- 取消以前会作为普通 Result 被捕获并跳过 finally。现在用私有 typed termination，
  普通 `domain/code/message` 不能伪造；取消/超时不被 catch 恢复，清理的 return/fail/panic
  不能替换原原因。嵌套 finally、scope、子任务共享绝对截止时间，只能缩短不能续期。
  普通 scope 清理超期为 `task/shutdown_timeout`，不误把继续执行的父任务标成 Cancelled。
- 超时发生在被调函数时，之前仅能看见被调 Env，调用者尚未 unwind 的子任务没有立即
  收到取消。新增 call-scoped Weak 绑定观察；动态读取当前 owning cell，避免参数 move/
  重绑定后的过期快照，并识别活动借用中的原 owner。HTTP 请求隔离观察栈和执行上下文，
  不把 handler 超时扩散到外层 listener scope。
- 取消 queued Task 现在释放排队 frame/capture，不执行用户任务来“帮助”清理；完成、
  取消、claim、结果取出与 terminal 观察遵循同一结果锁。修复 await 先观察空结果、
  后读取刚完成终态而误报 already_awaited 的竞争；实际完成的 Owned payload 只消费一次。
- 修复 blocking job 从 queued 转 running 时 shutdown 可短暂看见两个计数都为零；
  消费端已退出时，发送失败重新读取父取消原因和期限，再释放迟到结果。所有 payload/
  capture drop 均离开结果锁，计数只回收一次。
- 复用 safepoint 和 HTTP deadline；清理中拒绝 async/await/sleep/I/O/blocking 提交和
  listener bind/listen/run，允许同步 close/drop。提交前拒绝不等于禁止普通参数求值副作用。
  增加 suppressed cleanup、cleanup timeout、unfinished child 计数。
- 冷诊断/清理上下文沿用一个堆指针，Env 保持一个 Vec 表示，避免改动把每个 KuError/
  Value 都放大。新增布局回归；纯同步、从未提交 Task 的运行跳过 caller 观察的分配。
- 实库测试暴露 native `Load().byte_len()` 和 `(Load()?).byte_len()` 被误降为间接调用。
  IR 现在有界、无副作用地识别已知 str receiver，复用原有临时值与 drop 路径；接收者
  只求值一次，非函数字段仍拒绝。新增 64 轮真实 C 分配/指针存活/精确释放测试。

### R1 macOS HTTP CI 失败的隔离修复

原 reader 在每次 read 前修改 `SO_RCVTIMEO`，当前时间转换限定 1–200 ms，
排除了零值或 timeval 溢出。Apple XNU 的
[`sosetoptlock`](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/uipc_socket.c#L4491-L4496)

标出 set-timeout/read 或 idle/drip/body 子场景，原始交错仍只是推断。

仅修改 `tests/native_http_test.rs`：Unix 测试读取器改为 poll 等待和单次
`recv(MSG_DONTWAIT)`，不在已关闭的连接上反复修改 socket option；保留原绝对
deadline、每次等待上限和响应字节界。EINTR 重新检查 deadline，POLLNVAL、poll
资源错误、sticky hangup 无数据等错误不得变成忙循环。Windows 算法不变，错误
诊断补调用阶段。没有修改 native HTTP 生产代码、配置、状态码或公开 API。
